# Mock Government Portal APIs — How to Run

This service simulates GSTN, PAN/Income Tax, Udyam, EPFO/ESIC, Make in India,
and Blacklist/Debarment verification APIs, backed by the synthetic
`bidders.json` dataset from Step 2.

## Setup

1. Place `bidders.json` (from Step 2) one folder above this file, i.e.:
   ```
   project/
   ├── bidders.json
   └── mock_apis/
       └── main.py
   ```

2. Install dependencies:
   ```bash
   pip install fastapi uvicorn --break-system-packages
   ```

3. Run the server:
   ```bash
   cd mock_apis
   uvicorn main:app --reload --port 8001
   ```

4. Open the interactive API docs (auto-generated by FastAPI):
   ```
   http://localhost:8001/docs
   ```
   This gives your whole team a clickable UI to test every endpoint — very
   useful for demoing "multi-portal integration" live to judges.

## Endpoints

| Endpoint | Simulates | Example |
|---|---|---|
| `GET /mock/gst/verify?gstin=...` | GSTN portal | `?gstin=02CTOPA0265W1Z9` |
| `GET /mock/pan/verify?pan=...` | PAN/Income Tax | `?pan=KLHWT1422Y` |
| `GET /mock/udyam/verify?udyam_number=...` | Udyam/MSME portal | `?udyam_number=UDYAM-MH-11-2714803` |
| `GET /mock/epfo/verify?bidder_id=...` | EPFO/ESIC | `?bidder_id=BID-00001` |
| `GET /mock/makeinindia/verify?bidder_id=...` | Make in India / local content | `?bidder_id=BID-00001` |
| `GET /mock/blacklist/verify?bidder_id=...` | Blacklist/Debarment registry | `?bidder_id=BID-00001` |
| `GET /mock/verify-all/{bidder_id}` | **All 6 checks in one call** — use this in the compliance engine | `/mock/verify-all/BID-00001` |
| `GET /mock/bidders?limit=20&offset=0` | Utility: paginated bidder list, for populating a frontend dropdown | |

## Why built this way

- Every response includes a `"source"` field (e.g. `MOCK_GSTN_API`) — when you
  later plug in a real government API, your backend/compliance-engine code
  barely changes, since the response shape stays the same.
- Unknown GSTIN/PAN/Udyam numbers correctly return **HTTP 404**, mimicking a
  real "record not found" response — useful for testing your compliance
  engine's error handling.
- `/mock/verify-all/{bidder_id}` is the one your **Compliance Engine (Day 4)**
  should call — it fetches all 6 portal checks in a single request, which is
  both realistic and efficient.

Build the **AI Document Extraction module**: bidders upload PDFs (GST
certificate, Udyam certificate, PAN card, etc.), and an LLM extracts key
fields (GSTIN, PAN, Udyam number) from the document. The Compliance Engine
then **cross-checks** the extracted values against these mock portal

portal has on record?" This is where genuine AI value gets added, beyond
just querying a database.
